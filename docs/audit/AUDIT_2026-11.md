## Checked and found sound

- **Secrets in the repo and history.** Scanned the tree and all 106 commits on every branch for Google, Anthropic, Supabase, JWT, GitHub, AWS and private-key patterns plus generic `key=`/`token=` assignments. The only hit is the `changeme` placeholder. No `.env` file was ever committed.
- **Itinerary owner scoping.** Every `/api/itineraries` route filters on `current_user.id`; a foreign id returns 404. Tags are per-user. Covered by existing cross-user tests.
- **Account endpoints.** Always act on the caller; no id in the URL.
- **Injection.** No string-built SQL, no `eval`/`exec`/`subprocess`/`shell=True`, no user-controlled file paths.
- **Backend-proxy pattern.** The frontend calls only its own `/api/*` and loads the Google Maps JS SDK. No other third-party request leaves the browser.
- **CORS.** Explicit origin list, no wildcard, no credentials.
- **Redis cache keys.** Directions, GBFS, transit, geocode and OSM keys hold no user-specific data.
- **Review queue and survey export.** Both require an `X-Admin-Key` header and fail closed when the key is unset. No pipeline CLI is reachable over HTTP.
- **Unreviewed Tier-2 data.** Tier-2 writes only to the queue table. The detail endpoint filters parking, transit, curb and congestion rows on `reviewed`. Local DB has no `reviewed = false` rows in those tables.
- **Hidden venues.** The 18 `listed = false` venues appear in no list path: `GET /api/venues` filters them, the static fallback and the frontend's name map hold only the original 6, and search and both pickers read the filtered list. They remain reachable by id, as intended.
- **i18n key parity.** `en`, `es` and `fr` have identical key sets (199). `zh-Hans` lacks only the six `_one` plural forms, which Chinese does not use.
- **Tier-2 model id.** `claude-sonnet-5` is a valid model id.

## 1A. Security

### SEC-01 · Critical · The Google Maps key in the public web bundle is unrestricted
- **Status:** **Needs Jonathan's call** — no code fix exists. Restrict and replace the key in Google Cloud (steps above).
- **Where:** `frontend/app/(tabs)/planner.web.tsx:60,87` (`EXPO_PUBLIC_GOOGLE_MAPS_KEY`); the key itself lives in Vercel env and Google Cloud.
- **What:** The key shipped in the deployed bundle (`AIza…`, same key locally and on `junction-travel.vercel.app`) answered **Directions API and Geocoding API requests with status `OK` from a script with no referrer**. It has no HTTP-referrer restriction and no API restriction.
- **Why it matters:** Anyone can copy the key from the site and bill Directions, Geocoding and Places calls to the project. This bypasses every rate limit in the backend and defeats the backend-proxy pattern. If the same key is also the server key, there is only one key to steal.
- **Fix (Google Cloud Console, not code):** create two keys. Browser key: restrict to HTTP referrers (`https://junction-travel.vercel.app/*`, `http://localhost:8081/*`) and to **Maps JavaScript API only**. Server key: restrict to Directions, Places and Geocoding APIs. Then **delete the current key**, since it has been public and unrestricted. Set a daily quota cap on each API.
- **Effort:** S

### SEC-02 · High · Trip endpoints have no access control and use sequential ids
- **Status:** **Fixed** `22c3ce9` — per-trip token, migration 0018, frontend sends it. Run the migration on Railway.
- **Where:** `app/routers/trips.py:51-187`, `app/schemas.py:73-75`
- **What:** All eight `/api/trips` routes are unauthenticated and address trips by integer id. Anyone can read, rename, delete, or add and remove stops on any trip by counting ids. `TripCreate.user_id` is accepted from the client and stored.
- **Why it matters:** One loop over ids deletes every in-progress plan, and a second user's planner starts returning 404s mid-session. Trips are also created without limit.
- **Fix:** give each trip an unguessable access token, returned once on create and required in an `X-Trip-Token` header on every other trip route (404 on mismatch). Drop the client-supplied `user_id`. Needs a new migration and a small frontend change.
- **Effort:** M

### SEC-03 · High · Rate limits are keyed on the proxy's address, not the client's
- **Status:** **Fixed** `aeeaf8e` in code. Takes effect only once `RATE_LIMIT_TRUSTED_PROXY_HOPS` is set on Railway (see the PR for the value and how to verify it).
- **Where:** `app/rate_limit.py:40-44`, `Dockerfile:24`
- **What:** `_client_key` uses `request.client.host`, and its comment says uvicorn rewrites that from `X-Forwarded-For`. Uvicorn only does so for proxies listed in `FORWARDED_ALLOW_IPS` (default `127.0.0.1`), which is never set. Behind Railway, and behind the Vercel rewrite in front of it, every request appears to come from the proxy.
- **Why it matters:** All users share one bucket. The `optimize` limit of 15/min and the `directions` limit of 20/min become global limits, so a handful of simultaneous users get 429s, and one abusive client locks everyone out. The limiter also cannot single out an abuser.
- **Fix:** make the trusted-proxy depth explicit (`RATE_LIMIT_TRUSTED_PROXY_HOPS`) and read the client address from that position in `X-Forwarded-For`. Needs a Railway env change and a check of which keys appear in Redis.
- **Effort:** S (code) + config

### SEC-05 · Medium · JWT verification does not require `exp` or check the issuer
- **Status:** **Fixed** `fdc629c` — issuer confirmed against the project's OpenID metadata.
- **Where:** `app/auth.py:71,78`
- **What:** `jwt.decode` verifies signature, audience and, if present, expiry. It does not require `exp` or `sub` to exist and never checks `iss`. Algorithms are correctly pinned per path.
- **Why it matters:** A validly signed token without `exp` would never expire. Checking the issuer ties tokens to this Supabase project.
- **Fix:** `options={"require": ["exp", "sub"]}` on both paths; `issuer=<SUPABASE_URL>/auth/v1` on the JWKS path.
- **Effort:** S

### SEC-06 · Medium · Request bodies and query params lack bounds
- **Status:** **Fixed** `ad70e81`.
- **Where:** `app/schemas.py:40-76` (trip, stop, leg), `app/schemas_itinerary.py:25-38`, `app/schemas_account.py:31`, `app/routers/routes.py:36-45`, `app/routers/directions.py:300-303`, `app/routers/vehicles.py:29`, `app/schemas.py:170-174`
- **What:** No length limits on trip and stop names (the column is 200 chars, so a longer value is a 500 on Postgres), no coordinate bounds on stops, free-text `origin`/`destination` forwarded to Google, unbounded `saved_plan`, tag lists, `default_modes`, `preferences`, reorder lists and polylines, and `decision`/`mode` as plain strings.

- **Fix:** add `Field` limits, coordinate ranges, enums and a `lat,lng` pattern; cap `saved_plan` size.

### SEC-12 · Medium · Tier-2 extraction trusts the model's quote and fetches without guards
- **Status:** **Fixed** `9573cb0`.
- **Where:** `app/services/venue_extract.py:115-131` (`_fetch_page`), `:134-150`, `:160-181` (`_validate_field`)
- **What:** (a) A field is kept if it has any non-empty `quote`; the quote is never checked against the page text, so a hallucinated or page-injected value with an invented citation reaches the review queue looking sourced. (b) Page text is concatenated into the prompt with no delimiter. (c) The fetch follows redirects to any host, including private addresses, and reads the whole body with no size limit. (d) The Anthropic client has no request timeout (SDK default is 10 minutes).
- **Why it matters:** The review queue is the last gate before venue facts go live, and reviewers rely on the quote. The pipeline is CLI-only, which limits the SSRF exposure.
- **Fix:** drop fields whose quote is not found in the page text; delimit the page; refuse non-HTTP(S) and private hosts on every redirect hop; cap body size; set a client timeout.
- **Effort:** S–M

## Found while fixing (Phase 2)

### BUG-01 · Medium · The route engine crashes when a GBFS e-bike is near a trip endpoint
- **Status:** **Fixed** `e5ba5cc`.
- **Where:** `app/services/route_engine.py` (`micro_leg_metrics`, `MODE_LABEL[vtype]`)
- **What:** GBFS reports electric bicycles as `ebike` (the live Bird feed has them around Venice, where two listed venues are). The engine has no mode for that type, so building a transit access or egress variant from one raised `KeyError`, and `/api/routes/optimize` returned 500. It needs an e-bike within 300 m of an endpoint and a walk of 10 minutes or more to transit, so it did not reproduce on nine live Venice trips; a stubbed test reproduces it every time.
- **Fix:** the engine only composes variants from vehicle types it has a mode for. Rankings for inputs that worked before are identical. Whether e-bikes should become their own option, with their own fare, is Jonathan's call.
- **Effort:** S

### OPS-01 · Low · The Spin GBFS feed returns 404
- **Status:** **Needs Jonathan's call.**
- **Where:** `app/ingest/gbfs.py:53` (`https://gbfs.spin.pm/api/gbfs/v2_3/los_angeles/gbfs.json`)
- **What:** The local backend logs `404 Not Found` for Spin's root feed on every refresh. The app degrades as designed (Bird and Metro Bike Share still load, the error is reported in `metadata.errors`), but Spin shows no vehicles and the UI still names Spin.
- **Fix:** find Spin's current LA feed URL and set it through `GBFS_PROVIDER_ROOTS`, or drop the provider. Not changed here: the right URL has to come from Spin.
- **Effort:** S

### MESS-13 · Low · One venue has two names
